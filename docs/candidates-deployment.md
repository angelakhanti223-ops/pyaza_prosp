# Анкеты кандидатов Concept Group

## Точки входа после обновления сервера

- `/candidates` — публичная пошаговая анкета с исходным HTML-дизайном.
- `/crm/candidates` — список кандидатов, поиск, статусы, заметки, ссылки на PDF.
- `/crm/candidates/pdfs` — закрытая папка «Анкеты PDF».

Доступ к CRM кандидатов и каждому PDF предоставляется только активному пользователю с `is_superuser=True`. Роли `manager`, `head` и флаг `is_staff` сами по себе доступа не дают. В ответ `/api/auth/me/` добавлен признак `is_admin`.

При отправке сервер проверяет поля и согласие, создаёт PDF и сохраняет PDF и карточку одной транзакцией в PostgreSQL. Повторная отправка с тем же `requestId` и ответами возвращает тот же номер; изменённые ответы с тем же номером отклоняются. PDF хранится в закрытом поле базы, не в публичном `/media/`. Папка PDF — представление этих файлов в CRM. Резервная копия PostgreSQL включает анкеты и PDF.

PDF содержит все поля, до пяти мест работы, текст согласия, ФИО, серверное время подтверждения (МСК), версию и SHA-256 текста согласия. Это фиксация отметки в форме; графическая подпись из образца не переносится.

Используется согласие из архива HTML-формы, соответствующее тексту на третьей странице приложенного PDF. Согласие на отдельной фотографии отличается; его персональные данные и подпись в проект не добавлены. Источник текста и схема полей: `backend/candidates/schema.json`. При изменении текста нужно одновременно обновить версию и текст в публичной HTML-форме и в схеме сервера.

Публичная HTML-форма обслуживается отдельно от общего React layout, без счётчика Метрики и без хранения ответов в localStorage. После успешной отправки поля удаляются со страницы. При закрытии незаполненной отправкой страницы ответы теряются.

## Обновление существующего сервера

Выполнить в `/opt/sletat` после получения изменений основной ветки:

```bash
git pull --ff-only origin master
docker compose -f docker-compose.prod.yml build backend frontend
docker compose -f docker-compose.prod.yml run --rm backend python manage.py migrate --noinput
docker compose -f docker-compose.prod.yml up -d --no-deps backend frontend
```

Сборка backend устанавливает ReportLab и шрифт DejaVu Sans для кириллицы. Миграция добавляет отдельную таблицу кандидатов, существующие туристические заявки не изменяет.

## Проверка публикации

1. Открыть `/candidates` без входа, заполнить тестовую анкету и подтвердить согласие.
2. Войти под существующим администратором в CRM: кандидат должен появиться в «Кандидатах» и «Анкетах PDF».
3. Открыть и скачать PDF: проверить ответы, кириллицу и согласие.
4. Открыть ссылку на PDF без входа и под менеджером — должен возвращаться HTTP 403.
5. На странице кандидата поменять статус и заметку, обновить страницу: значения должны сохраниться.

## Автоматические проверки

```bash
cd backend
python manage.py test candidates
```

Проверяются права на список, карточку и PDF (включая прямые ссылки и HEAD), защита изменений от CSRF, обязательность согласия, серверная валидация, идемпотентность, отсутствие неполной записи при сбое PDF и ограничение частоты отправки.
