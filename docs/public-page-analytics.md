# Статистика публичных страниц

В CRM → «Статьи» по умолчанию открывается «Все страницы сайта». Соседняя кнопка «Статьи» сохраняет прежний отчёт, исторические счётчики и методику измерения статей.

Общий отчёт показывает открытия публичных страниц, сравнение с предыдущим равным периодом, среднее активное время, объём измеренной выборки, график по дням и показатели по каждой странице. Доступны 7/30/90 дней, произвольный период до 366 дней и выбор страницы. Периоды включают обе границы, часовой пояс — Europe/Moscow. Среднее взвешено по числу измерений; неизвестная длительность исключена, измеренный ноль включён. День определяется временем начала просмотра. Общий накопительный счётчик начинается с установки этого обновления: старые просмотры статей не прибавляются к нему, чтобы не смешивать периоды и методики. Они сохранены в отдельном отчёте статей.

## Сбор

`POST /api/pages/read-event/` принимает `{path, view_id, active_ms, kind}`. На одно открытие создаётся UUID, а не идентификатор человека. Повторные и пришедшие не по порядку события обновляют одну запись; UUID нельзя перенести на другой путь. Активное время растёт монотонно, ограничено возрастом сессии на сервере с допуском 3 с и пределом 2 часа. Известные поисковые роботы исключены; rate limit — 240 запросов в минуту на IP.

`PublicPageTracker` установлен только в публичном layout. При переходе между pathname создаётся новое открытие; изменение query или hash не создаёт ещё одно. Скрытая или потерявшая фокус вкладка не накапливает время. Данные отправляются каждые 15 с и при уходе через beacon/keepalive; при возвращении из bfcache начинается новое открытие. Общий модуль `public/page-read-tracker.js` используется и Next.js, и отдельным HTML-конструктором Китая. `/china-tour-builder.html` и `/tours/china-constructor` объединены.

Положительный список публичных страниц задан на клиенте и сервере. Статьи разрешены только после публикации; несуществующие, будущие и черновые статьи не принимаются. CRM, админка, API, анкеты кандидатов и прочие служебные/неизвестные пути исключены на сервере даже при поддельном запросе. История ранее публичной статьи сохраняется при её архивировании или удалении.

Сохраняются только нормализованный путь, заданное сервером название страницы, случайный UUID открытия, серверные даты, накопленное активное время и признак измерения длительности. Query, hash, referrer, формы и данные посетителя в таблицу метрик не попадают. IP используется механизмом rate limit в кэше, не в этой таблице. Cookies и localStorage для общего счётчика не используются. Существующий отдельный трекер статей продолжает вести свой отчёт; один просмотр статьи попадает один раз в общий отчёт и один раз в отчёт статей — эти отчёты не складываются.

`GET /api/crm/pages/analytics/?start=YYYY-MM-DD&end=YYYY-MM-DD&path=/tours` доступен только сотрудникам с авторизацией, по той же политике, что отчёт статей. Ответ и клиентский запрос — no-store. Параметр path необязателен; полный каталог для селектора сохраняется при фильтрации. Пустые дни заполнены нулём, неизвестное среднее — null. Показатели не являются уникальными посетителями; сотрудники, открывающие публичный сайт, учитываются как обычные просмотры.

## Поддержка и установка

При добавлении публичной страницы вне `/blog/[slug]` обновить `PUBLIC_PAGES` в `backend/articles/page_analytics.py` и `PUBLIC_PAGE_PATHS` в `frontend/public/page-read-tracker.js`. Для новой отдельной HTML-страницы также подключить модуль автозапуска; анкеты и внутренние страницы его не подключают.

Миграция `articles.0032_page_read_sessions` создаёт только новую таблицу и индексы, не изменяя статьи или прежние измерения. Собрать backend/frontend, применить миграции новым backend-образом, затем перезапустить оба сервиса. Существующая инфраструктура API и авторизация сохраняются.

Проверки: Django `articles.test_page_analytics` и прежние тесты статей; `node --test tests/page-read-tracker.test.mjs` из frontend; production Next.js build и проверка типов. Тесты таймера используют имитацию DOM/часов, не браузер. Ограничения измерений: блокировщики, отключённый JavaScript, сбой доставки и закрытие браузера могут терять события. При потерянном первом пакете ограничение возраста серверной сессии может занизить время. Открытия не удостоверяют реальное чтение текста и не защищены от целенаправленной накрутки. Нагрузка и гонки на production PostgreSQL отдельно не проверялись.
