# Задачи, следующий контакт и браузерные уведомления

## Работа менеджера

Сохранение даты «Следующий контакт» в открытой локальной заявке сразу создаёт одну задачу на канбане, с ответственным из заявки, сроком и каналом связи. Повторное сохранение и перенос даты обновляют эту же задачу. При смене ответственного она переназначается. Снятие даты или закрытие заявки отменяет задачу. Выполнение, отмена, удаление контактной задачи или перенос в колонку «Выполнено»/«Отменено» очищают соответствующую дату в заявке; изменение срока непосредственно в задаче переносит и контакт. Более новая дата заявки не затирается старым завершением задачи. Новая назначенная дата повторно открывает контактную задачу. Ручные задачи по заявке сохраняются. План без ответственного создаёт неназначенную задачу и не отправляет персональные push до назначения исполнителя.

Автозадача помечена origin=next_contact и уникальным automation_key по ID заявки. Синхронизация выполняется при сохранении Lead, без ожидания Celery. Сервис перечитывает заявку под select_for_update и использует уникальность ключа. Постороннее обновление старой заявки не создаёт задачу по прежней дате контакта, если такой задачи ещё нет: массовой загрузки старых дат не происходит. Прямые QuerySet.update/bulk_update обходят сигналы; бизнес-пути сохранения контакта должны использовать Lead.save()/сериализатор. История прежних дат в отдельный журнал не добавлялась: одна контактная задача представляет текущий план.

Дата/время в форме контакта показываются в часовом поясе устройства и передаются с явным UTC offset через ISO. Уведомления проверяются каждую минуту по абсолютному моменту срока. Задержки очереди, сети и браузера возможны.

## Очистка импорта U-ON

Миграция kanban.0009 архивирует только задачи с заполненным uon_reminder_id, сохраняет сами записи, вложения и связи. В выводе migrate печатается фактическое количество. Ручные задачи с uon_record_kind/id без uon_reminder_id, локальные автоматизации, заявки, клиенты и данные в U-ON не удаляются. Архив скрыт обычным менеджером Task.objects и связанными списками/сводками, но доступен через Task.all_objects и Django admin. В admin есть фильтр по архиву и действие восстановления.

Импорт напоминаний выключен по умолчанию (`UON_IMPORT_TASKS=False`): защищены периодический импорт, точечные синхронизации request/lead и вебхук добавления задачи. Сам импорт заявки/клиента из вебхука сохраняется. Обычная синхронизация заявок, автоматизация цепочек в самом U-ON и выдача документов не отключаются. Если импорт осознанно включить настройкой, архивированные reminder-ID не воскреснут и не задвоятся. Старая очередь/воркеры должны быть остановлены при миграции, затем запущены на новом коде.

## Web Push

В CRM есть кнопки включения, отключения и отправки теста. Разрешение Notification.requestPermission запрашивается только при нажатии пользователем. Подписка привязана к текущим пользователю и входу в CRM. После выхода подписка деактивируется, браузерная подписка снимается и видимые уведомления закрываются. Истёкший/удалённый сеанс, неактивный пользователь или смена пароля останавливают серверную доставку. После нового входа может понадобиться повторное включение. В публичном layout запросов разрешения и регистрации worker нет.

Service worker `/crm-task-sw.js` имеет scope `/crm/`, не перехватывает запросы и не кэширует CRM. Ключ VAPID генерируется однократно в БД (WebPushKey), отдельно задавать секреты в .env не требуется. Приватный ключ, endpoint подписки и сессионный ключ не возвращаются в API конфигурации и не регистрируются в admin. При восстановлении сервера нужно сохранять БД с этой записью, иначе потребуется переподписка. В `WEB_PUSH_SUBJECT` можно задать контакт отправителя; по умолчанию используется публичный email агентства.

Celery Beat каждую минуту вызывает kanban.tasks.send_due_task_pushes. Отправляются только задачи текущего исполнителя со сроком <= сейчас, без done/cancelled и архива. Задачи без срока не вызывают push. Это напоминания по срокам, а не оповещение о каждом изменении задачи. До десяти задач объединяются в одно сообщение; уже отправленные на этот браузер задачи с тем же сроком повторно не шлются. Перенос на другой срок создаёт новое напоминание. Первое включение может напомнить и о текущих просроченных задачах.

TaskPushReceipt фиксирует приём сообщения push-сервисом, а не показ на устройстве. При сетевом сбое выполняется до пяти попыток с интервалом 2/4/8/16 минут; 404/410 отключают истёкшую подписку. Блокировка подписки сериализует одновременные проходы. Авария процесса после приёма провайдером и до фиксации БД теоретически может повторить сообщение. TTL сообщения — 5 минут. Шифрованный payload содержит только ID задач и сроки; название для уведомления worker получает заново из защищённого API и проверяет текущий аккаунт, исполнителя, открытость задачи и совпадение срока. Поэтому устаревшая задача или сменившийся аккаунт не показывают прежние данные.

Подписки принимаются только с HTTPS endpoint доверенных push-служб Chromium/FCM, Mozilla, Apple и Microsoft. Redirect при отправке запрещён. Это исключает произвольные HTTP-запросы на адрес, переданный клиентом. Для другого push-провайдера потребуется осознанное дополнение списка хостов после проверки его endpoint. Доставка зависит от браузера, ОС и доступности push-службы; полностью выключенный браузер/компьютер не гарантирует уведомление в момент срока. На iOS действуют ограничения Web Push для установленных веб-приложений; отдельный сценарий установки здесь не добавлялся.

API `/api/crm/task-push/{config,subscription,preview,test}/` требует авторизацию; изменения защищены обычным SessionAuthentication/CSRF. Получение заголовков для показа проверяет только собственные назначенные задачи. UI подключён ко всем авторизованным страницам CRM.

## Установка и проверка

Собрать backend, frontend, celery_worker, celery_beat и telegram_bot. Остановить старые backend/worker/beat/bot, выполнить migrate новым backend-образом и поднять сервисы. На production после этого открыть CRM, нажать «Включить уведомления», разрешить их для сайта и нажать «Проверить». Сетевая доставка до реального браузера/ОС проверяется этим тестом; автоматические проверки мокируют push-провайдера.

Автотесты покрывают создание/перенос/закрытие контактной задачи, недублирование, назначение, синхронизацию сроков, архив и отключённые пути импорта, авторизацию, защиту endpoint/ключей, привязку к сеансу, дедупликацию доставки, повторные попытки и отбрасывание чужих/устаревших уведомлений в service worker. Реальные миграции отдельно проверяются на синтетических старых задачах с сохранением ручных записей и вложений. Проверка гонок на production PostgreSQL и доставка в реальный push-сервис не выполняются в локальных тестах.

### Результаты проверки 24.10.2026

Новые серверные сценарии: 30 тестов проходят; service worker: 4 Node-теста проходят. Общий прогон kanban/leads/integrations: 240 тестов, 237 успешны; те же 3 сбоя воспроизведены на неизменённой базе ветки (210 тестов, 207 успешны): поиск менеджера только по имени и два устаревших ожидания запрета назначения заявок менеджером. Существующую политику доступа не меняли. Production build/TypeScript и ESLint новых файлов прошли. В прежней карточке заявки правило react-hooks/set-state-in-effect падает на неизменённом вызове load(); остальная проверка этого файла с отключением только этого правила проходит.

Реальная цепочка миграций проверена на отдельной SQLite-базе: 201 синтетическое импортированное напоминание архивировано, все 203 исходные задачи, две ручные записи и метаданные вложения сохранены; восстановление проверено. makemigrations --check для kanban не показывает отличий. Существующий drift модели leads (имена индексов/поле tour_operator) воспроизведён на базе ветки и в этот объём не включён. Рабочая CRM без авторизации недоступна, поэтому фактическая очистка production выполнится при migrate, а доставку на устройство нужно проверить кнопкой после включения. Браузерная проверка нового UI здесь не выполнена.


С 24.10.2026 статус и колонка задачи объединены. Порядок колонок больше не определяет завершение; подробности переходов и миграции — в [unified-crm-tasks.md](unified-crm-tasks.md).
