# Аудит публичных форм flypenza.ru — 31.10.2026

## Охват

Проверены все классы публичных форм из исходников: общая LeadForm (модальное окно, CTA и карточки туров, главная/направления/круизы/акции/контакты/о нас/команда), ChatWidget, обе версии горнолыжного теста, GiftCertificateForm, NewsletterForm, многошаговая анкета кандидата. Страница Бали в public/blog не имеет HTML-форм: её кнопки ведут в мессенджеры. Конструкторы Китая и каталог Калининграда используют общую форму с предзаполнением. Внутренние формы редактирования CRM не входят в этот аудит; сохранение CSRF для внутренних запросов проверено регрессионным тестом.

## Исправления

1. Подписка использовала SessionAuthentication и могла получать 403 CSRF при наличии CRM-cookie. SubscribeView теперь явно публичный без использования сессии. Исправление сертификата/обычной заявки из PR28 сохранено.
2. Автоматический UniqueValidator поля EmailSubscriber.email отклонял повторную подписку раньше намеренного update_or_create. Убрана только эта проверка, валидация email и согласия сохранена. Повторная подписка обновляет ту же запись; новая явная подписка реактивирует адрес, отказ в согласии этого не делает.
3. Ошибки API вида detail: string теперь нормализуются в массив полных сообщений. В квизах больше не теряется весь текст кроме первого символа. Общая LeadForm всегда показывает серверную ошибку, включая detail/non_field_errors; ранее наличие неизвестного ключа скрывало общий fallback.
4. Общий postJson для публичных заявок/подписки использует credentials: omit. Полномочия CRM не отправляются. Клиент CRM и его CSRF-заголовки не изменены.
5. NewsletterForm: блокировка повторного submit, обязательная галочка на уровне браузера, ссылка на условия рассылки, полный текст ошибки с сохранением email и возможностью повторить.

## Проверки и границы доказательств

42 серверных теста прошли: сертификаты, обычные заявки, согласия, подписка, анкета/PDF кандидата. В том числе настоящие сессии с enforce_csrf_checks=True, анонимные отправки, неправильные данные, отказ без согласия, повторная подписка, throttle 429, прежняя защита внутренних CRM-запросов. Все записи только в временной SQLite; очереди лидов замоканы, реальные письма и заявки не отправлялись.

7 frontend-тестов прошли: три согласий и четыре API (JSON-контракты публичных отправок, omit credentials, полный detail/field-errors, не-JSON ошибка сервера, сетевая ошибка). TypeScript и production build прошли.

В браузере на QA-fixture проверены отправка/повтор общей заявки, передача consent=false для маркетинга, полный текст 429, сохранение данных, ошибка/повтор/успех подписки. API fixture замокан; это проверка компонентов, не отправка на production. Для чата и обеих версий квиза выполнены просмотр обработчиков и проверка общего API-контракта; полный пошаговый браузерный проход каждого квиза в этом аудите не проводился. Многошаговая анкета проверена серверными workflow-тестами, без заполнения всей анкеты в браузере.

Read-only GET на действующий сайт: 24 адреса, все HTTP 200. Это подтверждает доступность страниц/документов/списка направлений, но не является сквозной отправкой в реальную CRM. Список адресов: public-forms-live-get-20261031.json. Дополнительно получены через публичный API все 18 опубликованных статей: встроенных HTML-форм и inline fetch-отправок в их содержимом не найдено (public-forms-articles-20261031.json). Реальные доставки уведомлений/UON без доступа к production-очередям не подтверждались.

Установка исправлений требует пересборки backend и frontend. Миграций и новых переменных окружения нет.
