# Подарочные сертификаты

Публичная страница `/gift-certificates` использует общий layout, шапку, подвал, палитру и шрифт главной flypenza.ru. Пункт «Подарки» добавлен в меню; квалификационные сертификаты остаются по прежнему адресу `/certificates`.

Заявка содержит имя, телефон, необязательный email, комментарий и необязательную сумму. Оплата на странице не принимается. Условия действия, использования, получения и возврата сертификата менеджер согласует до оплаты; неподтверждённые условия не опубликованы.

В форме две заранее отмеченные галочки. Первая объединяет обработку персональных данных и связь по заявке, обязательна для отправки. Вторая — информационные и рекламные рассылки; её можно снять и отправить заявку. Пометки «обязательно» / «необязательно» рядом с согласиями в форме не показываются. Полные тексты доступны по адресам `/gift-certificates/personal-data`, `/gift-certificates/communication`, `/gift-certificates/marketing`; имя и ИНН оператора взяты из документов владельца.

`POST /api/gift-certificates/` проверяет оба обязательных значения API, передаваемых из первой галочки, строгие boolean-значения, актуальную версию документов и поля. Сервер самостоятельно фиксирует дату, версию, тексты и выбор; клиент не задаёт текст доказательства. В `Lead.gift_certificate_application` сохраняется снимок согласий. Версия 2026-10-25.2 фиксирует способ получения `preselected_checkboxes_submitted`: запись отражает состояние заранее отмеченных полей при отправке и не выдаёт его за отдельное активное включение каждой галочки. Предвыбранные поля сами по себе не гарантируют действительного согласия на рекламную рассылку; этот правовой риск ранее сообщён владельцу. В привычном комментарии CRM видны сумма, пожелания и состояние согласий. Фоновая синхронизация U-ON, оповещение менеджера и задача первого контакта ставятся после коммита. Рассылки и маркетинговые флаги контакта включаются только по отдельному согласию; без него существующая отписка не меняется.

Тексты синхронизированы в `backend/leads/gift_consents.json` и `frontend/src/content/giftConsents.json`, равенство проверяет тест. При изменении формулировок обновлять обе копии и версию. Предыдущие снимки в заявках не перезаписываются. Новая миграция `leads.0021_lead_gift_certificate_application` добавляет пустой JSON к старым заявкам, исторические согласия не подразумеваются.

Страница входит в sitemap и каталог общей статистики просмотров. Юридические документы не индексируются.

Автономный предпросмотр: `docs/previews/gift-certificates.html`. В нём нет отправки в CRM; все данные остаются в браузере. Тексты согласий открываются в диалоге, в рабочем сайте — на отдельных страницах. Мобильная шапка и чат автономного примера упрощены; рабочая страница использует штатные компоненты.

Иллюстрация `frontend/public/images/gift-certificate-coast.webp` создана встроенным Imagegen по приложенному визуальному референсу, исходник не менялся. Промпт: фотореалистичный кремовый подарочный сертификат с тёмно-синей атласной лентой и золотым самолётом на каменной террасе над средиземноморским побережьем; фотографии тропического моря и европейской архитектуры, оливковые ветви, тёплый вечерний свет; без текста и логотипов. На странице отмечено, что это иллюстрация.

Проверки: `python manage.py test leads.test_gift_certificates`; `node --test frontend/tests/page-read-tracker.test.mjs`; `npm run build -- --webpack`; `npx tsc --noEmit`. Серверные проверки запускаются в изолированной SQLite-базе, внешние отправки подменены; реальные обращения не создавались. Дополнительные старые отличия модели и миграций (переименования индексов и поле tour_operator) воспроизводятся и на исходном master, к этой доработке не относятся.

На самой странице сертификатов общая кнопка заявки направляет в форму сертификата; мобильная кнопка подписана «Подарить путешествие». Проверка статического предпросмотра в браузере: первый экран, форма, открытие согласия, демо-отправка без рассылок, ширина 390 px (контент 375 px со скроллбаром), отсутствие горизонтального переполнения. Отправка проверена серверными тестами; в публичной CRM тестовые обращения не создавались.

Регрессионная выборка первоначальной версии: 15 из 16 серверных проверок прошли; прежний тест `LeadCrmCreateTests.test_manager_cannot_assign_lead_to_someone_else` ожидает 400, получает 201. Тот же сбой отдельно воспроизведён на исходном checkout до доработки. Все 8 новых проверок сертификата и 5 тестов статистики прошли. Финальная production-сборка выполнена на актуальном master с конструктором Китая.

Версия интерфейса 2026-10-25.2 изменена по прямому указанию владельца: две заранее отмеченные галочки без пометки о необязательности. Старые снимки согласий сохранены без изменений. После снятия первой отметки форма не отправляется; после снятия второй заявка принимается без подписки.
