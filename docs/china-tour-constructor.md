# Онлайн-конструктор тура в Китай

Страница: `/tours/china-constructor`. Основа — предоставленный файл `emotions_china_tour_builder.html`. Сохраняется светлое оформление EMOTIONS. На странице `/tours` добавлена ссылка, адрес включён в sitemap. Страница обслуживается как самостоятельный HTML через существующий механизм rewrites; внутри неё нет iframe, шрифты и изображения загружаются с сайта. Канонический адрес задан в метаданных. Существующий конструктор Шанхай + Пекин сохранён.

## Расчёт

Пять городов: Пекин, Шанхай, Санья, Чжанцзяцзе и Фуронг. Семь стартовых маршрутов, изменение порядка остановок, отелей, количества ночей, транспорта, трансферов, экскурсий и дополнительных услуг. Пять готовых программ с фильтрами и описаниями. Месяцы формируются на ближайшие 12 месяцев, начиная с текущего.

Исходные числовые тарифы и модель сохранены из файла пользователя: расчёт на двух взрослых в одном номере с вылетом из Москвы, коэффициент `K=1.1`, базовый курс `USD=89.6682`, медицинская страховка `INS_NIGHT=1500`, помощь с картой прибытия `MIG_PERSON=1000`. Тарифы и сезонные коэффициенты заданы внутри HTML. Подключения к авиакомпаниям, системам наличия отелей или курсу валют нет. Сумма явно обозначена как предварительная; актуальное наличие, питание, документы, покрытие страхования и итоговую стоимость подтверждает менеджер. Другой состав туристов указывается в заявке и требует отдельного расчёта.

Самостоятельное заполнение карты прибытия бесплатно; платная строка расчёта обозначает помощь агентства. Трансфер из аэропорта или вокзала для Чжанцзяцзе и Фуронга в исходную модель не входил — это теперь явно указано в предупреждениях и описании.

Сборка сохраняется локально под ключом `flypenza-china-builder-v1`. Контактные данные туда не записываются. Ссылка содержит только параметры маршрута, без имени и телефона. Неверные и повреждённые значения нормализуются или заменяются стартовым маршрутом с уведомлением. Ограничения: до 8 остановок, от 1 до 14 ночей на остановку.

## Заявки

Форма отправляет запрос в существующий публичный `POST /api/leads/`, который Caddy направляет в backend. Поля: `name`, `phone`, `direction`, `initial_comment`, `consent=true`, `source=site_form`. ID направления «Китай» определяется по публичному `/api/directions/`; при недоступном справочнике остаётся null, страна присутствует в комментарии.

Для своего тура в комментарий входят маршрут, месяц, выбранные отели, транспорт, экскурсии, дополнительные услуги, смета и ссылка на сборку. Для готового тура передаётся выбранная программа с её условиями и ценами, без случайной подстановки маршрута из конструктора. При выборе «Подобрать тур с нуля» непрошенная сборка не добавляется. Даты, пожелания и состав туристов из формы включаются отдельно.

Есть проверка имени, телефона и согласия со ссылкой на политику. Успех показывается после успешного ответа API. При ошибках данные остаются в форме; повторные нажатия во время запроса блокируются. После сетевой ошибки без подтверждения идентичная отправка блокируется до изменения данных или перезагрузки — результат предыдущего запроса сначала нужно проверить с менеджером. Это не серверная гарантия уникальности заявок. Отправка формы не является подтверждением бронирования.

Ссылки на мессенджеры сохранены как отдельное действие посетителя. Никаких автоматических сообщений через мессенджеры страница не отправляет. Счётчик Метрики в исходном файле равен нулю; идентификатор не придумывался.

## Проверка

- Полная production-сборка Next.js 16.2.10/Turbopack и TypeScript завершились успешно. ESLint изменённых TypeScript-файлов и проверка синтаксиса встроенного JavaScript — без ошибок.
- На настоящем standalone-сервере проверен URL rewrite `/tours/china-constructor` при ширине 1440, 390 и 320 px. Горизонтального переполнения, ошибок JavaScript, отсутствующих изображений или запросов к сторонним ресурсам при работе с калькулятором нет.
- Проверены изменения стоимости от ночей, отеля, экскурсий, страхования и помощи с картами прибытия; сумма разделов равна общему итогу. Проверены все семь стартовых маршрутов, месяц, добавление/удаление/перестановка городов, сохранение и восстановление ссылки, повреждённые данные, фильтры готовых туров и клавиатурные вкладки.
- Заявки своего и готового тура, согласие, ошибки API 400/503 и блокировка двойного нажатия проверены только с тестовыми ответами. Боевые обращения в CRM не создавались. Работу очередей уведомлений/UON эта проверка не подтверждает.
- Отдельный HTML-предпросмотр содержит встроенные изображения и шрифты и атрибут `data-preview`, отключающий отправку заявок. Проверен на 1440 и 390 px без внешних запросов. В рабочем HTML из репозитория этого атрибута нет.

## Установка после согласования

Изменения затрагивают только frontend. После включения ветки в master: обновить код, собрать и перезапустить frontend. Новые миграции базы для этой страницы не требуются. Чтобы проверить реальные заявки после установки, нужна отдельная согласованная проверка через публичную форму.
