# Цели офиса: октябрь и ноябрь 2026

Раздел `/crm/goals` читает планы из `leads.OfficeGoals`. Вверху доступен выбор октября или ноября. План, чекбоксы и факт не смешиваются между месяцами.

- Октябрь сохранён из прежней страницы: оборот 4 млн ₽, 200 лидов, конверсия 30%, комиссия 200 тыс. ₽, все 17 пунктов по соцсетям, развитию, продукту и операционному контролю. Прежний показатель комиссии по бронированиям сохранён.
- Ноябрь: оборот 5 млн ₽, 150 лидов, конверсия 30%, поступление комиссии 220 тыс. ₽, комиссия с новых бронирований 9%. Факт поступлений вводится вручную и хранится отдельно. Ноль и отсутствие факта различаются.
- Ручные цели ноября — 15 чекбоксов: три направления, бизнес-завтрак, CRM, пять статей, листовки, две визитки и две цели по операторам. Начальные отметки не заданы. Прежняя страница октября не хранила состояния выполнения.
- Изменения отметок и поступлений доступны пользователям с прежними правами управления, требуют CSRF и сохраняются в БД. Изменение одного пункта не заменяет остальные отметки.
- Процент комиссии — взвешенный по одним и тем же бронированиям с заполненными суммами в RUB. Количество использованных записей показано на странице. Конверсия сохраняет действующее правило управленческого дашборда.
- График ноября хранится в `WorkShift`: Катя начинает 1 ноября, далее 3/3; по 15 смен у каждой. Октябрьский график не меняется.

## Установка на действующий сервер

После переноса изменений в `master`:

```bash
cd /opt/sletat &&
git pull --ff-only origin master &&
docker compose -f docker-compose.prod.yml build backend frontend &&
docker compose -f docker-compose.prod.yml run --rm --no-deps backend python manage.py migrate --noinput &&
docker compose -f docker-compose.prod.yml up -d --no-deps backend frontend
```

Миграции 0023–0026 добавляют график, структуру целей и планы двух месяцев. Повторный запуск заполнения целей не стирает ручные отметки и введённые суммы. Миграция графика определяет сотрудников по существующим логинам `elena` / `ekaterina`, затем по именам; `admin` используется только как запасной вариант для Елены. При отсутствии сотрудников выводится предупреждение без частичного заполнения; при неоднозначности установка останавливается до выбора правильных сотрудников.

Проверки выполняются на отдельной тестовой базе. Доступ к рабочей БД и установка на сервер не подтверждаются изменениями в GitHub.
